# PRD — Bilibili DLC Getter

## 产品目标

让用户**粘贴一个 B 站链接，就能把这个活动 / 装扮下的全部图片素材拿到手，并且拿到手就能用**。

「拿到手就能用」是本项目区别于「网页批量下载器」的核心目标：不止是把图存下来，还要把两类素材加工成平台可直接使用的形态 —— 表情拼图切成单张表情、头像挂件嵌上自己的头像。

## 用户与使用场景

### 目标用户

- B 站数字周边 / 个性装扮的收集者，想要留存或转用活动素材；
- 需要把 B 站官方表情包导入微信 / QQ / Discord 等第三方聊天工具的用户；
- 想用 B 站头像挂件装饰自己头像、但不想在 B 站 App 内完成的用户。

用户具备的基本能力：会用浏览器、能复制链接、能解压 ZIP。**不要求**任何图像编辑技能。

### 典型场景

| 场景 | 用户动作 | 期望结果 |
|------|----------|----------|
| **A. 收集活动素材** | 粘贴数字周边活动链接 → 解析 | 看到「卡片」「收集品」两个分区，逐张浏览；一键把整区打成 ZIP 下载 |
| **B. 导入表情包** | 在「收集品」区找到表情包卡 → 点 ✂️ | 弹出预览 dialog，红蒙层标出将被裁掉的区域；确认无误后点「确认切割」→ 得到一个 ZIP，里面是切好的单张表情（动的仍是动图） |
| **C. 网格推断不准** | 场景 B 中发现切割线偏了 | 在 dialog 里直接改行数 / 列数 / 边距 / 间距，预览实时重绘，改到满意再确认；关掉重开仍保留刚才的微调 |
| **D. 做头像** | 在「收集品」区找到头像框 / 头像挂件卡 → 点嵌入按钮 → 选本地头像 | 弹出合成 dialog，看到自己的头像已套进挂件；调半径让头像大小合适 → 确认 → 得到一张 PNG |
| **E. 抓个性装扮** | 粘贴装扮详情页链接（无 `lottery_id`）→ 解析 | 看到空间背景 / 主题皮肤 / 表情包 / 卡片等分类分区；表情包分区展开了全部子表情，而非只有封面 |
| **F. 链接失效 / 活动下架** | 粘贴一个已下架活动的链接 | 看到明确的业务提示（「可能该活动暂无数字周边」「可能该装扮已下架」），而不是一串网络报错或空白页 |
| **G. 分享抓取结果** | 抓取成功后复制地址栏 URL 发给朋友 | 对方打开链接后页面自动从路径提取参数并发起抓取（无需再次粘贴），标题栏显示活动名 |
| **H. 快速切换链接** | 解析完一个活动后想抓另一个 | 点输入框右侧 × 一键清空，焦点自动回到输入框；或直接粘贴覆盖 |

## 核心问题

1. **B 站没有提供「导出素材」的能力**。活动页只能逐张右键另存，一个包几十张图就是几十次操作，且右键另存下来的文件名是无意义的哈希。

2. **表情拼图不能直接用**。官方表情包的收集品图是一张 5×5 / 4×5 / 3×5 的拼图大图，聊天工具需要单张。手工切割意味着：数格子、算边距、逐格裁剪、补成正方形、动图还要逐帧处理 —— 对普通用户不可行。

3. **网格参数每张图都不一样，且肉眼不可靠**。同样是「5×5」，外边距可能是 56/40，也可能满幅零间隙；贴纸之间可能有空隙，也可能紧贴甚至跨格宽构图；动画里贴纸会移动，单帧看是断开的，联合起来看是粘连的。**这是本项目最难的问题**，也是用户最不可能自己解决的问题。

4. **动图切割会丢动画**。用普通图像工具打开动画 GIF 只能看到首帧，切出来的是一堆静止图。必须逐帧解码、逐格重编码，还要处理「这一格其实是静止的，不必编成 GIF」。

5. **头像挂件是半成品**。挂件图中心是透明圆孔，用户需要把自己的头像精确地圆形裁剪到合适的半径再叠上去 —— 半径靠肉眼试错，且每次都要重做。

6. **浏览器跨域限制**。B 站 API 不允许浏览器直接跨域请求，纯前端方案必须借助代理；B 站 CDN 有防盗链，直接 `fetch` 图片需要绕开 `Referer`。

## 功能及其意义

| 功能 | 解决什么 | 为什么需要 |
|------|----------|------------|
| **链接解析与类型自动判定** | 用户不需要知道自己在抓「数字周边」还是「个性装扮」，也不需要手动挑出 `id` / `lottery_id` | 两类链接长得像（都是 `?id=...`），但走完全不同的 API。让用户选会引入误操作；含 `lottery_id` 即判为 DLC，否则判为装扮，判定成本为零 |
| **分区画廊浏览** | 替代「逐张右键另存」 | 一屏看全一个活动的素材结构；分区标题带数量，用户能立刻确认抓全了没有 |
| **原图全尺寸预览 + 放行原生右键菜单** | 单张快速取图 | 不缩放、不压缩，右键即得原图。不拦截浏览器菜单是刻意的：用户本来就熟悉这套操作，强行替换只会增加学习成本 |
| **分区批量 ZIP 下载** | 整区一次性取图 | 场景 A 的主路径。ZIP 内文件名带序号 + 清洗过的中文名，不再是哈希 |
| **表情包网格参数自动推断** | 核心问题 3 | 这是把「手工切割不可行」变成「确认一下就行」的关键。推断覆盖：常规带间隙网格、贴纸紧贴（1px 缝隙判为噪声）、跨格宽构图、动画道具越界行间、满幅零间隙（退回接缝颜色剖面）、行内大面积粘连（靠动画分裂帧恢复格线） |
| **切割参数预览 dialog（红蒙层 + 白描边）** | 推断不可能 100% 准 | 红蒙层直观展示「哪些像素会被裁掉」，白描边标出保留格。用户不必理解任何参数含义就能判断切得对不对 |
| **8 参数实时微调** | 核心问题 3 的兜底 | 行数 / 列数 / 上下左右外边距 / 行间距 / 列间距全部可调，改一个像素预览立刻重绘。把「推断」降级为「初始值建议」，最终决定权在人 |
| **动图逐格重编码** | 核心问题 4 | 动格输出动画 GIF（保留每帧时长与透明），整格无变化的输出 PNG。同一张拼图里动静混排也能各得其所 |
| **切片补成 1:1 方形** | 聊天工具对表情尺寸的要求 | 内容居中、透明填充。是否严格 1:1 如实标注 —— 用户改了参数导致非方时，标识消失，不骗人 |
| **dialog 首开后保持挂载** | 场景 C 的迭代工作流 | 关闭再打开仍保留刚才的微调，用户可以「切一次 → 看产物 → 回来改 → 再切」而不必从头调参 |
| **头像挂件半径自动推断** | 核心问题 5 | 从圆心向四向扫描首个不透明像素，取次大值 —— 与主体装饰留安全距离，同时允许凸出装饰自然叠压头像 |
| **头像合成所见即所得预览** | 核心问题 5 | 预览像素即最终产物（棋盘格只是透明区底衬）。用户调半径时看到的是真实结果，不是示意 |
| **个性装扮分类展开** | 场景 E | 装扮 API 的图片藏在每个条目的 `properties` 里，字段名不固定；表情包的真身还嵌在 `items[]` 子项里。不递归展开就只能拿到一张封面 |
| **业务化错误文案** | 场景 F | 区分「链接格式不对」「活动暂无内容」「装扮已下架」「网络请求失败」，各自给出可行动的提示，而不是抛栈 |
| **失败重试** | 网络抖动 | 保留上次解析参数，错误态一键重试，不必重新粘贴链接 |
| **MD3 主题（浅色 / 深色 / 跟随系统）** | 长时间浏览与截图观感 | 默认跟随系统实时切换；点击后固定在浅色 / 深色两态。Canvas 预览的棋盘格与蒙层颜色也读主题令牌，深浅色下都看得清 |
| **响应式布局** | 移动端使用 | 画廊网格 240px → 160px 降档；切割 dialog 宽屏左右分栏、窄屏上下堆叠；步进器触摸目标 ≥ 40px |
| **地址栏 RESTful 路径 + 入口自启动** | 复制链接给他人直接打开即可看到抓取结果，无需二次粘贴 | 解析成功后 `history.pushState` 写入 `/dlc/<id>/<lottery_id>` 或 `/garb/<itemId>`；页面首次加载时从 pathname 反向提取参数自动发起抓取 |
| **页面标题同步** | 浏览器标签页显示活动 / 装扮名称，而非固定站点名 | 抓取成功后 `document.title` 更新为 `{活动名} - Bilibili DLC Getter`；多标签页一眼可辨认内容 |
| **卡片图片原始尺寸展示** | 用户无需右键查看图片属性就能知道素材分辨率 | 每张卡标题下方以浅色字展示 W×H 像素尺寸；对表情包切割判断格尺寸、对挂件判断模板大小均有参考价值 |
| **输入一键清除** | 粘贴完链接、解析完后想贴新链接时快速清空 | 输入非空时右侧出现 x 按钮，点击清空并自动回焦输入框；避免手动退格逐字删长链接 |
| **个性装扮分区顺序优化** | 头像挂件因排在末尾容易被遗漏 | pendant 分类从九分类末尾前移至第三位（空间背景→主题皮肤→**头像挂件**→表情包→…），高使用率分类更早呈现 |

## 功能之间的关系

```
                        粘贴链接
                           │
                     链接解析与类型判定
                      ╱            ╲
              数字周边(DLC)      个性装扮(garb)
                     ╲            ╱
                    统一的分区数据结构
                           │
                     分区画廊浏览 ──────────► 原图右键另存（最轻路径）
                           │
                     分区批量 ZIP 下载（中等路径）
                           │
              ┌────────────┴────────────┐
        收集品带 emoji 标记        收集品带 pendant 标记
              │                          │
      ✂️ 切割表情包                  嵌入头像（选本地文件）
              │                          │
      网格参数自动推断              圆孔半径自动推断
              │                          │
      预览 dialog + 8 参数微调     预览 dialog + 半径微调
              │                          │
      静图切 PNG / 动图逐格 GIF      圆形裁剪 + 模板叠加
              │                          │
           ZIP 下载                    PNG 下载
```

三条取图路径**从轻到重、互不阻塞**：右键另存（1 张、0 步）、批量 ZIP（整区、1 步）、加工下载（单张、需调参）。用户按需选择，不需要为了拿一张图去理解网格参数。

两项加工能力（切割 / 合成）共享同一套交互范式：**自动推断初始值 → 预览 dialog 可视化 → 参数微调 → 确认才下载**。共享 `ParamStepper`（步进器）与 `canvasUtils`（主题令牌 / 棋盘格）两个公共件，dialog 尺寸、按钮布局、取消语义完全一致。

## 范围与非目标

### 范围内

- 两类 B 站链接的解析与素材抓取（公开 API，无需登录）。
- 分区浏览、原图另存、整区 ZIP 打包。
- 表情包网格切割：参数推断 + 预览微调 + 静图 / 动图产物。
- 头像挂件合成：半径推断 + 预览微调 + PNG 产物。
- MD3 主题切换与移动端响应式。
- 业务化错误提示与失败重试。

### 范围外

- **后端服务**：不实现、不托管、不改造 CORS 代理；不做任何服务端抓取、缓存或转码。
- **账号与鉴权**：不登录、不带 Cookie、不抓取需要登录态或购买后才可见的内容。
- **通用图像编辑**：不提供自由裁剪、旋转、图层、滤镜、文字、批量调色等能力。切割与合成都是**单一用途、参数化**的工具。
- **表情包的二次创作**：不做拼图（反向操作）、不做表情改图、不做动图帧率编辑。
- **数据持久化**：不存历史记录、不存用户偏好（主题选择刷新即回到跟随系统）、不做收藏 / 标签。
- **视频 / 音频素材**：装扮里可能有 `.mp4`（点赞动画等）；只收白名单内的图片扩展名（png / jpg / jpeg / webp / gif / apng），视频一律忽略。
- **B 站以外的平台**：不解析其他站点的活动链接。
- **e2e 的 API mock**：测试一律打真实接口。这意味着 e2e 会随 B 站数据变化而波动，是已知且被接受的代价。
